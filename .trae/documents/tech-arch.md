## 2. 数据流（一次问答）
1. 前端 POST /api/chat 携带多轮消息。
2. 接入层做 CORS / 限流 / 鉴权 / 入参校验。
3. 拒答闸门先跑「别名快判」：命中校园别名才放行，否则交给意图分类器兜底。
4. 语义检索引擎对「最后一条用户消息」计算向量相似度，取知识库 Top-3 片段。
5. 组装系统提示词（角色 + 防注入 + Top-3 片段）调用 DeepSeek。
6. 模型返回后，若命中知识库则追加【来源：文件名.txt】并标注徽标类型。
7. 前端按徽标类型渲染「知识库命中 / 大模型泛答 / 拒答」三态。

## 3. 语义检索引擎设计（RAG 升级）
- 切块：按【章节】→ 段落切块，单块 ≤ 600 字，块内记录文件名 + 章节标题。
- 向量化：轻量本地嵌入模型（@xenova/transformers · all-MiniLM-L6-v2，ONNX，经 hf-mirror 镜像）。
- 检索：查询向量与所有块向量做余弦相似度，取 Top-3。
- 降级：嵌入模型不可用时自动回退到 TF-IDF 余弦（仍优于关键词二元组）。
- 热更新：fs.watch 监听 documents/，按「文件名+mtime+size」指纹判重，变更即重建索引。

## 4. 安全纵深（四层）
1. 接入层：限流 + CORS 白名单 + 轻量鉴权。
2. 闸门层：别名快判 + 意图分类，拒答与检索解耦（先闸门、后注入）。
3. 提示词层：防间接注入指令，知识库内容视为数据。
4. 前端层：React 转义 + 来源徽标，杜绝 XSS 与不可信渲染。

## 5. 云端就绪
- 后端无状态 + 环境变量注入，可无缝迁移 Vercel / Cloudflare / 容器。
- api/（Vercel Serverless）与 server.ts（本地）共享同一套 lib 逻辑。
