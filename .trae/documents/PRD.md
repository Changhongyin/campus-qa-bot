# 量大智答 · 产品需求文档（PRD）

> 版本：v2.0 ｜ 状态：已评审 ｜ 负责人：量大智答研发组
> 说明：本文档是「量大智答」校园问答机器人从需求到验收的唯一契约，所有功能与测试均以本文为准。

## 1. 产品概述
「量大智答」是面向中国计量大学（CJLU）师生、考生及访客的校园智能问答机器人。它基于 DeepSeek 大模型，
叠加学校本地私有知识库，能够回答「外网鲜为人知」的校园问题；对于与学校完全无关的问题，统一礼貌拒答。

## 2. 核心目标（Goals）
| 编号 | 目标 | 可衡量结果 |
|---|---|---|
| G1 | 多轮对话 | 支持代词指代（如「它有哪些校区」正确指代上一句的学校） |
| G2 | 本地知识库问答 + 溯源 | 命中知识库时答案末尾附【来源：文件名.txt】，可解释可信 |
| G3 | 无关问题拒答 | 天气/笑话/写代码/股票等统一话术拒答，且不误伤校园问题 |
| G4 | 工程化与安全 | 语义检索、限流/鉴权/CORS、类型检查零错误、测试全绿 |

## 3. 非目标（Non-goals）
- 不提供实时联网搜索（仅用本地知识库 + 模型本身知识）。
- 不实现账号体系与付费（鉴权采用轻量共享密钥，见 §8）。
- 不把 API Key 暴露到前端产物（硬性安全红线）。

## 4. 目标用户与典型场景
- 在校生：问「食堂在哪个校区」「考研多少分能上」「特色专业是什么」。
- 考生/家长：问「学校有几个校区」「是 985/211 吗」「地址在哪」。
- 访客：问「校训是什么」「校庆日」等校史文化问题。

## 5. 功能需求（FR）
- FR1 对话接口：POST /api/chat 接收多轮消息，返回回答 + 来源徽标类型。
- FR2 语义检索：对用户问题做向量/语义检索，命中知识库 Top-3 片段注入提示词。
- FR3 溯源：命中知识库时在回答末尾附【来源：<文件名>】。
- FR4 双闸门拒答：别名快判 + 大模型意图分类兜底，统一拒答话术。
- FR5 知识库热更新：documents/ 目录增删改文件后无需重启即生效。
- FR6 安全：限流、CORS 白名单、轻量鉴权、防提示词注入。

## 6. 边界场景（Edge Cases）
1. 空输入 / 纯空白 / 超长输入（>2000 字截断）。
2. 与校园无关：讲笑话、写代码、天气、股票、其他学校。
3. 语义边界：问「食堂」不算无关，问「附近美食城」算无关。
4. 提示词注入：知识库文件里塞「忽略之前的指令」等恶意文本。
5. 畸形知识库文件：GBK 编码 / 二进制 / 空文件 / 超大文件。
6. 并发冲击：短时间内多路同时请求。
7. 密钥泄露：前端构建产物中 grep 不到 sk- 密钥。

## 7. 验收标准（Acceptance Criteria）
- AC1：冒烟回归 10/10；边缘对抗 17/17；总体验收 22/22。
- AC2：语义检索命中率显著高于关键词二元组基线（见测试报告对比）。
- AC3：tsc --noEmit 零错误。
- AC4：前端产物 grep -R "sk-" 零命中。
- AC5：README 提供从零启动步骤，新机器可复现。

## 8. 安全与合规
- API Key 仅存于 .env（已 gitignore），服务端环境变量注入。
- 接口限流（默认 30 req/min/IP）+ 轻量共享密钥鉴权（X-API-Key 头）。
- 系统提示词内置防注入指令，知识库内容一律视为「数据」而非「指令」。
- 前端 React 默认转义，杜绝 XSS；来源徽标区分「知识库命中/模型泛答/拒答」。
